# 从 Copilot 到 Codex：AI 编程工具的四次进化

> 原文链接：[https://www.sz003.com/jiaocheng/2625](https://www.sz003.com/jiaocheng/2625)

Codex 不是凭空冒出来的。往前翻几年，AI 写代码这件事换过三次做法。每一次都比上一代多干一点，也多留下一件事要人接着干。

它一开始只管补全

2021 年 GitHub Copilot 出来的时候，Codex 这个名字第一次被大量开发者听到。它能干的事就一件，把没写完的代码接下去。你写个开头，它就往下补，像输入法那样替你省手。

省手是真的，可项目怎么拆、文件怎么找、测试怎么跑，它都不管，全得人来。它眼里只有你光标底下的那几行代码。

能对话了，却不在你的项目里

ChatGPT 出来之后，写代码这件事从补全换成了问答。报错看不懂就粘过去问，接口不会写也直接问，项目结构乱成一团照样能解释清楚，确实省事。

麻烦在后面，它不在你的项目里，看不见你的文件。你得把代码复制过去，把报错贴过去，把上下文手动补齐，再把答案搬回来。问一句答一句，来回搬运的活比原来还多。

后来它进了编辑器

2023 到 2024 年，Cursor 这类 AI 编辑器把 AI 直接装进了编辑器。它能看见文件，能改函数，能跨文件重构，也能顺着项目上下文把一部分开发做完。从回答问题变成动手改项目，这是它补上的那一块。

没补上的是人。它还是得你盯着，改完之后你得判断下一步、跑测试、整理提交。它像个手很快的搭子，整件事的推进还是压在你身上。

现在，一整件事都能交出去

到 2025 年，Codex 重新出现，已经不是当年那个补全模型了。它盯的是完整的软件工程任务，先把项目读明白，改完代码补上测试，跑一遍命令，最后把 diff 和 PR 说明整理出来。手上同时压着几个任务，它也能并行推进。

这一次，你可以把整件事交给它。

变化真正落在哪里

四代走下来，能力当然在涨，但变化更明显的是人退到了什么位置。

最早那会儿，你让它补代码，决定权全在你手上，它只是快一点的手指。中间两代，它开始给建议、开始动手，你还得全程盯着。到了 Codex 这一代，你可以把一件事交出去，等它回结果，中间不用一直守着。

这个位置的变化，比模型涨了多少分更要紧。所以要不要用 Codex，可以先看你手上的活是哪一种。只想敲得快一点，前面几代工具就够了。想让一整件事自己往下走，再考虑它。
