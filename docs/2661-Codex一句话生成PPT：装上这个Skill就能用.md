# Codex 一句话生成 PPT：装上这个 Skill 就能用

> 原文链接：[https://www.sz003.com/jiaocheng/2661](https://www.sz003.com/jiaocheng/2661)

手上有现成的社区 Skill，装它却是件麻烦事。手动整理目录，放对位置，检查依赖，一套下来半小时就没了。把 Skill 的仓库地址交给 Codex，让它自己读仓库，判断依赖，完成安装。这件事就压缩成一句话。

第一步：让 Codex 装，别自己整理目录

社区里不少开发者会把自己做好的 Skill 放在 GitHub 仓库里，公开给别人安装和复用。这个案例用的是 guizang-ppt-skill 这个 PPT 技能，仓库地址就是它的全部来源。

装它的提示词很短。请帮我安装这个 Skill，安装完成后告诉我它的用途，依赖要求，以及应该如何调用。

末尾那三个要求别省掉。光装上没用，你得同时知道它能干什么，要什么依赖，怎么把它叫出来。

不同工作区的安装方式不完全一样。有的直接支持安装，有的会先把仓库结构分析一遍，再回来问你确认放置位置和依赖要求。被追问是正常的，如实回答就行。

装完立刻拿一个真实任务验证

装完不要放着。直接给它一个真实任务，看这个 Skill 到底能不能跑通。

示例提示词是：请使用刚刚安装的 PPT Skill，根据 AI 编程工具入门这个主题生成一份适合分享的演示稿，先告诉我还缺哪些关键信息。

上下文给不够的时候，Codex 会先回到这个 Skill 的操作手册里，看它需要什么输入，再回来向你追问。你补齐背景，主题，受众和风格之后，它会按 Skill 的流程往下走。先读 README，模板和相关文档，然后生成结果。

如果这个 Skill 的默认产物是 HTML 演示稿，通常可以直接在 Codex 内置浏览器里打开预览。

装完之后重点检查四件事

&#8211; 装的是不是你指定的那个 Skill，而不是名称相似的别的仓库

&#8211; 安装后有没有说明依赖要求，输出格式和调用方式

&#8211; 生成结果是否落在这个 Skill 原仓库描述的能力边界内

&#8211; 结果不理想时，是 Skill 本身的限制，还是你给的输入不够

社区 Skill 的风险在哪

它不是官方能力，质量和维护状态差异很大，用之前先看仓库 README。

还有一点容易误判。给出 GitHub 链接不等于一定能一步装成功，有些 Skill 依赖额外脚本，模板或者本地环境，缺一样就跑不起来。

第一次验证挑个不起眼的小任务。确认 Skill 能正常运行，再拿它去做正式产物。
