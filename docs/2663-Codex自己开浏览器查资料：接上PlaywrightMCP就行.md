# Codex 自己开浏览器查资料：接上 Playwright MCP 就行

> 原文链接：[https://www.sz003.com/jiaocheng/2663](https://www.sz003.com/jiaocheng/2663)

改完前端代码想让 Codex 自己确认页面跑通了，光看代码它做不到。Playwright MCP 补的就是这一环。它是基于 Playwright 的 MCP 服务器。它把打开浏览器，访问网页，点击按钮，填写输入框这些操作封装成 AI 能调用的工具。读页面内容，截图，验证结果这几项也在里面。

装上之后，Codex 这类编程 Agent 除了写代码改代码，还能打开网页像人一样检查页面。

装法：一条命令加一次核对

命令行里跑这一句完成安装：codex mcp add playwright npx @playwright/mcp@latest

装完进 Codex，用 /mcp 命令列出当前已经安装的 MCP 服务列表。列表里有 playwright 就说明装上了。

拿一个查资料任务试它

核对通过之后，用一个测试任务看它到底能不能干活。任务分三步，打开浏览器搜什么是 MCP，找几篇相关教程，把搜索结果存成本地 Markdown 文件。

提示词可以直接这么写：请打开浏览器，到百度搜索什么是 MCP，选择两篇优质内容阅读，并整理成一个 markdown 文件保存在当前目录。

权限得手动放几次

执行过程中要放开一些权限，它才能调用相关工具。填写搜索框，填写文本，打开网页这几类操作，在未授权的情况下都需要手动放行。

放行的时候自己看一眼动作是什么再点。想少点几次，可以在规则里把这几类浏览器操作提前放行。

跑起来能看到什么

执行过程中它会打开浏览器，搜索相关内容，再打开两篇文章，这些全都能看到。

最后它把结果总结输出，写入本地的 Markdown 文件。文件里的内容是 Codex 读完那两篇文章之后归纳出来的说明。

结果文件里应该有什么

生成的 Markdown 文件里，主要是那两篇文章内容的归纳和说明。Codex 读完选中的两篇之后，会把里面的要点重新组织一遍再写进去。

检查的时候看两点。文件里有没有出现文章里的具体内容，以及归纳出来的说法是不是原文的意思。这两点对上了，说明它真的读进去了，而不是只截了个标题。

什么时候值得用它

页面能不能跑通这类验证最合适。写完前端，改完接口，让它自己开一遍页面，比人工点一遍快。

不涉及浏览器的工作就别开它。权限放开了用不上，反而多一层风险。
