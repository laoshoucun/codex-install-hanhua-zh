# Codex CLI 命令速查：参数、斜杠命令和报错对照

> 原文链接：[https://www.sz003.com/jiaocheng/2649](https://www.sz003.com/jiaocheng/2649)

CLI 是 Codex 里最适合练基本功的入口。终端里没有多余的按钮，每条命令你都能看清它要去做什么，改起来也随时能打断。

这一篇按使用频率排，先弄清三种使用姿势分别适合什么，再看交互和一次性执行的写法。启动参数那部分按用途分类，参数名和默认值会跟着版本变，记住哪一类管哪件事就够了。

交互模式是默认入口，熟悉一个仓库和逐步改代码都走它。重复动作要交给脚本或者流水线的时候用 codex exec，它执行完就退出。一个任务跨了几次还没做完，用 codex resume 把上下文接上。

交互模式：第一句话先限定边界

进入项目根目录再启动 codex，第一句话别急着让它改东西。先让它只读一遍仓库。项目用途，入口文件，安装与测试命令这几项要报回来。然后再要一份建议优先补齐的文档和测试清单。这么做的好处是你能看出它理解到什么程度，后面的任务才有准头。

交互模式真正的价值是能中途停下。它准备执行命令之前，你可以先确认这条命令要干什么，也可以把一个任务拆成几轮慢慢推进。

一次性任务用 codex exec

codex exec 适合放进脚本，CI 或者重复任务里。跑完进程就结束，没有追问的余地，所以任务说明要比交互模式写得更死。

它常被用来批量生成仓库摘要，或者在一个 CI 失败之后自动收集失败原因。为 release notes 生成初稿，从日志里提炼排查建议，也属于这一类。输出格式可以直接写进任务里，例如项目概览控制在一百二十字以内，技术栈用表格呈现，风险提示最多五条。

恢复会话之前，先留一份阶段总结

长任务经常要分段推进。每个阶段结束的时候，让 Codex 留下这几样：

已经读了哪些文件

改了哪些文件

跑过哪些命令

还没完成的下一步

当前的风险

下次恢复时，把上一段的总结原样贴回去当第一条消息，上下文断裂会小很多。

斜杠命令是用来观察状态的

斜杠命令用于在会话里快速查看状态，或者执行一些常用动作。不同版本的命令列表会变，最稳的方式是在 CLI 里打一个斜杠，看当前有哪些。

跑完第一次实战，手上应该留下几样东西。diff 要小到一眼能看完，一条验证命令要能重复跑出同样的结果。改动摘要得说得清楚，另外还得留下一份能反复用的任务模板。最省事的一步是先把只读分析固化成习惯，每次拿不准就先让它读，不动手。
