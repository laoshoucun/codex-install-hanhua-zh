# Codex 从零做网站（下）：管理后台、招商 PPT、宣传视频

> 原文链接：[https://www.sz003.com/jiaocheng/2674](https://www.sz003.com/jiaocheng/2674)

上篇把页面放到了网上，这一步给它配三样东西。一个能管商品的管理后台，一份拿去谈合作的招商 PPT，一条能直接播的宣传视频。三件事都还在同一个项目里做，节奏也还是计划模式那一套。

它们看起来是三种活，实际走的是同一条路。先交代需求，看它给出的方案，确认效果，最后提交到 Git。区别只在最后产出的是一个页面，一份文档，还是一段视频。

管理后台依旧从计划开始

管理后台接着上篇的仓库做。依旧先使用计划模式，让它把方案摆出来，看过再往下走。确认没问题，提交到 Git 保存代码。

这一步和加销量，加热销榜没有本质区别，只是改动的范围更大。计划模式在这里的价值更明显，后台牵扯的页面和数据结构比前端多，先看计划比事后改结构省事。

招商 PPT 借一个 Skill 生成

PPT 这类成品文档，用现成的 Skill 比自己从零描述快。把 GitHub 上对应 Skill 的地址发给 Codex，安装这一步它自己就能完成。

装好之后在对话框里输入一个斜杠，从列表里选中这个 Skill，把招商 PPT 的要求交给它。最后检查生成结果。它给出的是一份完整的招商 PPT，成品上传到了云端，按提示的链接可以下载查看。

宣传视频用插件生成

视频走的是插件这条路，案例里用的是 HyperFrames。装好插件之后，先用计划模式生成视频方案，再看效果预览。最终成品是一条宠物零食的宣传视频，上传到云端后可以直接在浏览器里播放。

Skill 和插件在这里的分工不太一样。Skill 交给它的是一套做法，插件带进来的是外部工具的能力。视频这种要调外部引擎或者服务的活，通常落在插件这边。

三样东西连起来看

前端能卖货，后台能管货，对外的招商和宣传各有一份可以拿出去的成品。同一个小项目从页面一路做到物料，用的还是那套四步节奏。先交代需求，看它给出的方案。确认效果没问题，再提交到 Git。这四步在前端用得顺，搬到后台和物料上一样顺。

这类 Skill 和插件大多来自第三方。用之前先看清它从哪来，重要项目先在测试目录里试一遍，再往正式项目上搬。
