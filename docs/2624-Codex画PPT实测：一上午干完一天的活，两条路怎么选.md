# Codex 画 PPT 实测：一上午干完一天的活，两条路怎么选

> 原文链接：[https://www.sz003.com/jiaocheng/2624](https://www.sz003.com/jiaocheng/2624)

做行业分析、对标分析这种活，以前是收集资料，整理框架，一页一页往下做，一天就交代在里面了。

现在换个干法。需求直接丢给 Codex，让它先出一版可编辑的 PPT，人工再收个尾。实测下来，一上午能顶过去一整天的活。

先把边界说清楚，别期待过头。咨询类的内容对逻辑表达要求高，Codex 出的稿子还得人来调，逻辑链条得有人把关。日常的汇报演示类 PPT，它出来的基本能直接用。想省时间，就从这类页面下手。

具体走法有两条。

干脆一点的那条，全程在 Codex 里完成。先让它用 skill 生成页面图片，再用 skill 把图片转成可编辑的 PPT。适合不想来回切工具的人。

另一条是让 Codex 出图，GPT 转写。先生成页面图片，再把图丢给 GPT，让它照着图做一份可编辑的转写。这条路实测效果意外地好，GPT 照着图画出来的还原度不错，而且比 Codex 自己转快不少。代价是烧算力额度，用得多了一次性把 GPT 的用量顶到上限，后面几天只能歇着。

GPT 转出来为什么越来越能打，它自己给过一段解释，值得琢磨。它现在把任务理解成按原页的视觉结果，重建一份可维护的 PPT，而不是把 PDF 里的对象直接转换成 PPT 对象。

这两个目标差别很大。前者允许它做取舍，复杂的底图不硬拆，上面的文字、数字和关键框架全部重做，保证你后面还能改。咨询表格这类会认真重建，因为你之后大概率还要动里面的内容。后者只是把对象机械搬一遍，搬完基本改不动，只能当图片看。

按这个逻辑，最适合这个玩法的是结构明确的页面。咨询报告，战略 PPT，表格，架构图，能力地图，流程图，数据页，这类页面它能做到看起来几乎一样，同时还能继续编辑。

反过来，设计感极强、靠复杂底图和版式吃饭的页面就不太适合，硬拆容易拆坏。对像素级还原有要求、需要原样复刻的场合也一样，它做的那些取舍反而帮倒忙。

喂给 GPT 的图越清楚，转出来的越准，模糊截图别指望它脑补。额度这件事也别不当回事，一条条转写很爽，一周的量几天用完，后面只能干瞪眼，重要的任务记得排在前面。收尾这步更别省，输出的是可编辑，不等于可以直接发，数字、措辞、逻辑还得人过一遍。AI 吃掉的是那部分重复劳动，剩下的一小段，恰恰是它暂时替代不了的地方。

先把结构明确的那类页面交给它，用一上午的时间，验证一下这条路值不值得留在你的工作流里。
