# Codex总犯同样的错？搭好这套工作区架构，让它越用越聪明

> 原文链接：[https://www.laoshoucun.com/jiaocheng/2623](https://www.laoshoucun.com/jiaocheng/2623)

桌面一份，下载文件夹一份，文档目录里再翻出几份，用 Codex 干活的人，多半见过它这么收拾新项目的场面：代码，文档，脚本随手一扔，下个任务派下去，它得把整台电脑翻遍才摸得清核心文件在哪。这还只是毛病之一，另一种窝火更磨人，上回刚纠正过的错误，这一回它照样犯，你只能像带新人一样把同样的话再交代一遍。

两个毛病表面不相干，病根却是同一个：这台智能体手里既没工作规范，也没记忆沉淀，每回开工都等于拿一张白纸上阵。药方其实不复杂，在 workspace 里搭起一套架构，让复盘、记踩坑账都变成它自己的事。思路先前讲过一次，后台催实操细节的人不少，这篇把做法拆开说透。

第一步，在桌面给 workspace 安个家

Codex 装好后别急着派活，先去桌面新建一个 workspace 文件夹，往后所有项目都从这里起步。文件夹里摆三份文档，一人管一段：

全局工作台：接手新项目之前的必读入口，地位等同最高指令，每份文档干什么用，文件按什么规矩命名，都在这里写明白。

全局复利与踩坑日志：错犯在哪、哪些做法值得留着反复用，全往这里装。对产出不满意的地方，能沉淀下来的套路，也一并收进来。

新项目 SOP：规矩定死，每接一个新项目，就得新建"project+编号+项目名"的文件夹，代码和文档，脚本一律归进对应文件夹，电脑别处一个都不许落。

日志会不会攒成一本厚账，每回开工都得从头念到尾。不必有这个担心，全局工作台本身就把这件事管起来了：Codex 哪回干砸了、哪回干漂亮了，自己提炼要点补进日志，平日要用再翻。一句话，工作台发号施令，日志管沉淀，SOP 看住文件去向，三份文档互不插手。

一串编号文件夹，就是它的导航

这套规矩跑上一阵，workspace 里会长出一排带编号的文件夹："project001-某某项目""project002-某某项目"，这么依次排下去。这排名字的用处有两层：往浅了说，文件各归各位，管理上不再闹心。往深了说，打开 workspace 瞄一眼文件夹名，过往做过哪些项目、眼下该重点盯哪几个文件，马上就有谱。等于 GPS 给它装好了，满机器扫盘找文件的环节整段砍掉。

真正定生死的一步：给 AGENTS.md 立规矩

架子立起来，新麻烦跟着来：凭什么保证它每次接活都先把三份文档过一遍，而不是跳过去直接动手。钥匙在它的底层记忆中枢，AGENTS.md。这个文件从你装好 Codex 那天起就待在核心项目文件夹里，你的使用习惯、沟通偏好，最要紧的要求，全记在里面，而它每次启动都得先读一遍。

所以整套架构里真正定成败的动作，是往 AGENTS.md 里写进一条压过一切的规则：不管项目大小，动手前先把全局工作台、全局复利与踩坑日志，新项目 SOP 三份文档读一遍，确认读完才开工。干的过程中踩过什么坑、攒下什么能复用的东西，一项项归进对应日志。

怕手写？这活儿一条指令就能外包

写到这里，怕是有人开始发怵：这么一堆文档，难道要我亲手一个个敲出来。想多了，搭架子这件事本身就能派给 Codex 去，下面这条指令，原样复制发给它即可：

帮我在 workspace 里创建一个全局工作台的文档，用于规范 Codex 的行为规则。再帮我创建一个全局复利与踩坑日志的文档，用于记录犯过的错误、踩过的坑，走过的弯路以及未来可以持续复用的方法。最后帮我创建一个新项目 SOP 的文档，要求每执行一个项目必须要创建一个 project+编号+项目名称的文件夹，而且所有相关的内容全部需要存放到对应的文件夹当中，不能放到电脑的其他位置。同时把以上的命名规范、各个文档的使用规则，包括文档的目录结构，全部汇总到全局工作台里面。在做完以上所有的事情之后，一定要在我的 AGENTS.md 文档这个记忆中枢里面写入一个最高优先级的指令：在未来执行任何新项目之前，必须先查看全局工作台、全局复利与踩坑日志以及新项目创建的 SOP 这三个文档，确认阅读完成以后再执行新的任务。

指令一出手，后续全是它的事。往后再派新项目，它按既定规矩先读文档、再建文件夹，收尾时自己复盘，自己总结，自己打磨。

丑话说在前头：这架构装完不会当天显灵。踩坑日志得攒上一两周，复利效果才一点点显形。日志本身也要定期让它自己瘦身，不然只进不出、越滚越厚，开工前的阅读负担反倒水涨船高。花十分钟把结构搭起来，换的是往后每次派活少费一轮口舌，账摆在这儿，怎么算都是赚的。
